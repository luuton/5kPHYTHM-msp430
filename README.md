# 5K 下落式节奏游戏 — MSP-EXP430F5529

> 在一块 8 KB RAM / 128 KB Flash 的 MSP430 上，用 5 路电容触摸焊盘做一个 60 fps 的下落式音游（5K 5 轨）。
> 无音频硬件，纯**目押**（看谱打点）。判定精度靠微秒级时基 + 时间戳判定，不靠帧率。

## 这是什么

MSP-EXP430F5529 是一块外设密度很高的实验板：102×64 单色液晶、5 路电容触摸焊盘、三轴加速度计、
齿轮电位器、8 个 LED、2 个机械按键、RTC、USB、SD 卡座。常见用法是逐个点亮它们。

本项目把这些外设**全部纳入同一个实时系统**，做成一个能玩的节奏游戏：

- 音符从屏幕顶部沿 5 条轨道下落，玩家在判定线处用手指击打对应的电容焊盘
- 判定精度以**毫秒**计：PERFECT ±30 ms / GREAT ±60 ms / GOOD ±100 ms
- 单色液晶跑**稳定 60 fps**（16.7 ms 帧周期）
- 板载无蜂鸣器/DAC，玩法是**目押**（纯视觉），靠 LED 与背光构建第二条快速反馈通道

## 技术要点

### 1. 判定用「时间戳」，不用「处理时刻」

这是整个设计能成立的前提。触摸扫描与渲染都是采样/帧式的，但**判定计算完全基于事件时间戳**：

```
音符到达判定线的时刻 t_ms  vs  击打事件的时间戳 songT
dt = t_ms - songT  →  分级
```

因此：

- **输入延迟 = 扫描采样误差（实测 ±1.3 ms），不是帧时间（16.7 ms）**
- 帧率下降只影响视觉流畅度，**不影响判定精度**

击打时间戳取「扫描中点」（扫描前后各读一次时基取中值），进一步压低抖动。

### 2. 40 ns 时基

Timer_A0 以 SMCLK 25 MHz 连续计数（1 tick = 40 ns），溢出中断扩展为 32 位。
读取时关中断 + 检查 `TAIFG` 补偿，避免「硬件已溢出但 ISR 未执行」的读数竞态
（该竞态会让耗时测量无符号回绕成 4.29 s）。

**⚠ 32 位 tick 只有 171.8 秒**（2³² × 40 ns）。早期 `Time_NowMs()` 直接取
`ticks / 25000`，于是每到 171.8 秒毫秒值就倒退 171798 ms：`songNow = now - startWall`
变成 4.29e9，**所有音符瞬间判成 MISS、轨道清空**，看起来就是"铺面消失 + 卡死"。
现在毫秒改由溢出中断里的独立 32 位累加器维护（每次溢出 65536 tick = 2.62144 ms，
小数部分留在 `ms_frac` 累计），回绕周期 **49.7 天**。`Time_NowUs()` 仍用 tick 除法，
只用于"短间隔求差"。

### 3. 影子缓冲 + 批量推屏

原厂 HAL 是**写穿式**的：每个绘制原语立刻发起 SPI 事务，逐像素绘制一帧约需 50 ms（≈20 fps），项目直接不可行。

本项目绕开它：绘制只写 `shadow[8][102]`，一帧结束再 `setAddress + writeData(102)` × 8 批量推屏。
实测量化：绘制影子缓冲 **4.9 ms** + SPI 推屏 **2.2 ms** = 一帧渲染 **≈7.1 ms**（占 16 ms 预算 44%）。

**⚠ LCD 与 SD 卡共用 USCI_B1。** `msc_Init()` → `disk_initialize()` → `HAL_SDCard_init()`
会把 UCB1 改成 SD 卡上电要求的 **397 kHz**（`BR0 = 63`）并翻转时钟极性。之后推屏一帧要
**17 ms**、整帧 26~30 ms，输入盲区翻倍、手感明显变差。这个副作用**只在初始化过 USB 之后出现**，
极容易被误判成"USB 中断干扰触摸"。`RTLCD_RestoreSpi()` 在 `msc_Init()` 之后立刻把 UCB1
恢复成 `UCCKPH + BR=2`（12.5 MHz），推屏回到 2.2 ms。

### 4. 多键同时识别

TI 的 `TI_CAPT_Buttons()` 只返回**一个**主导电极，不能用于 5K。本项目用 `TI_CAPT_Custom()`，
它保留每路原始 `delta` 值，于是可以自己做逐路判定：

```c
thr   = Touch_Thresholds[i] * Touch_SensPct / 100;   /* 灵敏度倍率，设置界面可调 */
按下  = delta[i] >= (上一帧已按下 ? 0.6*thr : thr);   /* 迟滞：杀阈值悬停抖动 */
主导键 = 只与"自己也过阈值"的邻居比较，取较大者；
         相等时判给小轨号；                              /* 平局裁决 */
```

这四条规则都是被实测数据逼出来的（`T` 行带五路 delta，可直接验证）：

- **迟滞 60%**：同一路在 0~30 ms 内重复上报过 27 次（阈值悬停），释放门限降到 60% 才停
- **只比较"过阈值"的邻居**：旧写法拿原始 delta 比，lane1 的**底噪 125** 会把 lane0 的
  真按压（120，阈值 112）压掉 → **漏按**
- **平局判给小轨号**：手指压在两个焊盘中间时两路读数会被拉成同一个数，旧规则两边都放行
  → 按一个键亮两个 LED
- **卡键自愈**：某路连续 1.5 s 判为按下且幅度 < 2×阈值（基线漂移导致的假按住），
  重标该路基线并立即释放

**测量尖峰**：CTS 的 fRO 方法本质是"数软件循环次数"（`while(!(TA1&TAIFG)) j++;`），
测量期间进一次中断就会让 `j` 偏小而 `delta` 虚高到 1200~3300（真按压只有 300~900）。
根因在中断，已在 HAL 里**逐路关中断**（每路约 260 µs，远小于 USB 全速 1 ms 帧）彻底消除；
`game_touch.c` 里保留 >900 整组重测一次的兜底。

### 5. 菜单键轮询取代 ISR

原厂 `HAL_Buttons` 的 ISR 有三个问题：不打时间戳、`buttonsPressed` 是赋值而非或（和弦会丢）、
实际没有消抖。菜单对时间精度要求只有 ±20 ms，因此改用主循环轮询 + 3 帧（≈50 ms）消抖，
天然规避全部三个问题。

### 6. 旋钮读取不做阻塞等待

原厂 `Wheel_getValue()` 用 `__bis_SR_register(LPM0_bits + GIE)` 等 ADC 中断，
**中断一旦丢失就永久睡死在 LPM0**（且 `lab1.c` 的 RTC ISR 只在 `RTCExitSec==1` 时才清 LPM 位，
所以每秒的 RTC 中断也唤不醒它）。本项目实测出现过一次 **24823 ms 的单帧卡死**，
正发生在调用旋钮读取的菜单界面。

`game_menu.c` 改为**有界轮询 + 超时返回无效值**，绝不挂死；抖动门限沿用 HAL 的 ±10 counts。

### 7. 暂停恢复要有冷启动时间

暂停期间玩家的手和注意力都离开了，**直接恢复会导致一上来就连掉几个音符**。
所以恢复分两步：按 S2 先进入 `PL_RESUME` 状态，谱面**冻结在暂停位置**（`songNow`
不再推进）、中央显示 5 秒大字倒计时；倒计时结束才搬移 `startWallMs`
让曲目时间从暂停点无缝续上。

倒计时期间击打被忽略（`Play_Tap` 只在 `PL_PLAYING` 生效），避免误判。

### 8. 谱面结束条件

```c
tEnd = min(length_ms + 500, lastNoteMs + GOOD窗 + 600)
结束条件 = songNow > tEnd && 全部音符已判定
```

- 用 `min` 而不是 `length_ms`：`length_ms` 是手填字段，与音符列表无关。
  实测三张谱的尾部空转有 3~5 秒，按末音符时刻算可省掉这段时间
- 保留 `length_ms` 作为上界：它是"曲子总长"的声明（含前奏/尾奏），不该被无视
- 加"全部判完"兜底：万一 `length_ms` 被填得比实际谱面短，光靠时间会提前跳结算，
  尾巴上的音符永远得不到判定（表现为 `R` 行求和 ≠ 音符总数）

### 9. 遥测走 USB CDC

判定是看不见的，所以把关键数据打出来：击打事件（含 dt）、每秒帧/扫描统计、结算统计、
参数标定。输出为纯 ASCII 行，任意串口助手可读，也可重定向存盘后用脚本分析。

**为什么用 USB CDC 而不是 UART**：

- 一根线同时供电和通信，不需要外接 USB-TTL
- CDC 发送**非阻塞**（端点忙则丢弃），而 UART 一行 70 字符要阻塞 6 ms
- 电脑端免驱，出现一个虚拟 COM 口

**时钟初始化**：USB 需要 4 MHz XT2 作为 PLL 参考，序列完整复刻 LAB4 的 `ClockUSB()`：
`P5SEL |= 0x0C`（把 XT2 引脚切到晶振功能）→ `SELREF/SELA = REFO` →
`Init_FLL_Settle(25000, 762)` 重锁 25 MHz → `XT2_Start(XT2DRIVE_0)`。
这几步的顺序不能乱：先让 FLL 用内部 REFO 稳住 MCLK，再启动 XT2，
否则 XT2 起振期间的 OFIFG 会拖累 FLL。

**枚举死锁自愈**：实测出现过主机还没开始枚举、SIE 先报一次 suspend 的情况，
`USB_suspend()` 把 `USBIE` 收窄成只剩 `RESRIE`（`0x0020`）。此后主机发 RESET 只会把
`RSTRIFG` 置位、中断永不触发，设备再也走不到 SETUP 阶段（实测 `USBIE=0x0020`、
`USBIFG=0x0080`，`tSetupPacket` 永远是 RAM 残留值）。`Usb_Poll()` 里做了两层兜底：轮询标志位接管
中断漏掉的 RESET（拉低 D+ 20 ms 做一次真插拔后重新武装 `USBIE=0x00C4`），
以及把漏掉的 SETUP 交给栈自己的 `SetupPacketInterruptHandler()` 处理。
**一旦成功枚举过就再不做这件事** —— 否则会把正在使用的 COM 口打断
（表现为"打开串口失败/被占用"）。

**接口号不能硬编码**：本工程是 MSC+HID+CDC 复合设备，`descriptors.h` 里
`CDC0_INTFNUM = 1`。传错接口号会命中别的端点，表现为"发送永远 busy"。

**返回值不是 `kUSB_succeed`**：`USBCDC_sendData()` 成功时返回
`kUSBCDC_sendStarted`（`0x01`），而通用 USB API 的成功值是 `kUSB_succeed`（`0x00`）。
拿后者比较会把每次成功发送都判成失败 —— 表现为"USB 枚举正常但一个字都发不出来"。

**单行必须 ≤ 64 字节**：USB 全速端点单包上限。V 行（参数）与 K 行（阈值）
就是因此拆成两行的，C 行也重新压缩过 —— 否则会被截断成半行乱码。

**启动 XT2 必须防两件事**（本工程实际踩过，整机卡死）：

1. `USB_enable()` 内部用原厂 `XT2_Start()`，那是 `while (SFRIFG1 & OFIFG)` **死等**。
   XT2 不起振就永久卡死。`game_usb.c` 里改用带计数上限的 `xt2_start_guarded()`，
   失败时跳过整个 USB 启用（游戏照常运行，遥测不可用），绝不阻塞。
2. `LAB1main` 里 `SFRIE1 |= OFIE` 打开了晶振失效中断，而本工程**没有
   `UNMI_VECTOR` 的 ISR**。XT2 起振期间 OFIFG 短暂置位会触发 UNMI 并落空 → 卡死。
   正确做法是配置晶振前后 `SFRIE1 &= ~OFIE` / 恢复（`LAB4` 的 `ClockUSB()` 也是这么做的）。
3. `USB_handleVbusOnEvent()`（`USB/USB_User/usb_eventHandling.c`）原本直接调
   `USB_enable()`。VBUS 中断每触发一次就会走那条死等路径 —— 这才是"卡在 LOGO 屏、
   按键无反应"的直接原因。已改为先问 `Usb_Xt2Ready()`，未就绪直接跳过。

**另外**：清晶振故障标志时只清 `XT2OFFG`，**不要**清 `DCOFFG` / `XT1LFOFFG` ——
MCLK 由 FLL 以 XT1 为参考锁定，清掉 XT1 的故障标志会掩盖真实故障；
一旦 FLL 失锁、SMCLK 停摆，主循环里所有基于 `Time_NowMs()` 的等待循环都会死锁
（表现为"卡在某一屏"）。

**开机诊断**：LOGO 页第三行会显示 `USB ok` / `USB fail`。
- `USB fail` → XT2 未起振，USB 物理上不可用（检查板上 4 MHz XT2 晶振）；
  此时把 `TELEM_BACKEND_USB` 改成 `0` 可回退到 UART 继续调试
- **`USB:suspend` 且电脑完全看不到设备** → 最可能是 **USB 线是"只充电线"**
  （VBUS 有电但 D+/D- 不通）。此时设备端看到 VBUS、拉高 D+，却收不到任何
  SOF，3 ms 后 USB 模块自己转入 suspend。**换一根数据线**再试；
  或先跑 LAB4 的 EchoUSB 对照，确认线/口本身可用
- `USB ok` 但电脑仍认不到 / COM 口要等十几秒才能打开 → 描述符是 MSC+HID+CDC 复合设备，
  主机在探测那个**永远不会响应的 U 盘**。`Usb_Poll()` 里每帧非阻塞跑一次
  `USBMSC_poll()`，让它立刻回答"无介质"即可缓解；彻底解决是裁成纯 CDC（见待办）

## 实测性能

| 指标 | 实测值 | 备注 |
|---|---|---|
| 帧周期 | **16 ms（稳定 60 fps）**，最长帧 16~17 ms | 帧体约 15 ms，其余为空闲 |
| CTS 全扫耗时 | **1.37 ms**（min）/ 1.5 ms（avg） | 每帧前 4 ms + 渲染后填充扫描 |
| 渲染 | **≈7.1 ms** = 绘制 4.9 ms + 推屏 2.2 ms | 占帧预算 44%（`F` 行后三列） |
| 内存占用 | RAM ≈ **5.6 / 8 KB** | 谱面镜像 2496 B（416×6）+ 影子 816 B + 栈 512 B |
| USB 枚举 | 插上后 1~2 s 内 COM 口可用 | 见技术要点 §9（MSC 轮询 + 自愈） |

> 数据来源：`Debug/LAB1.map` 与 USB 遥测的 `F` 行。

单局实测（Easy 谱，88 音符，`OFF=+10 / WIN=30 / SENS=250`）：
**PERFECT 47 / GREAT 31 / GOOD 6 / MISS 4，maxCombo 47，得分 8136**；
连续 4 局 PERFECT 率稳定在 51%~63%。

## 串口遥测协议

**USB CDC 虚拟串口**（默认）。板上 USB 口与烧录口是**两个独立接口**，可同时连着。
电脑端免驱，设备枚举后出现一个 COM 口 —— 波特率对 CDC 无实际意义，任选即可。

备用后端：把 `game/game_telem.h` 里的 `TELEM_BACKEND_USB` 改成 `0`，
即切到 **USCI_A1 UART（P4.4 = TXD / P4.5 = RXD，115200-8-N-1）**，
需要外接 USB-TTL。两种后端共用同一套行格式。

纯 ASCII、空格分隔、可 grep。行缓冲 **128 字节**（USB 端点按 64 字节自动分包）：

```
V 5k-r58 spd=60 off=+ 10 aln=+ 3 win=30/60/100  # 开机横幅：固件 tag + 可调参数
K thr=112,175,153,225,180 sens=150              # 基准阈值 + 灵敏度倍率
T 00123 2    1700    1694  -  6 PERFECT |    0   30  801   28    5
                                                # 击打：序号 lane note tap dt 判定 | 五路 delta
T 00124 0     ---    1300   --- WRONG   |   63    0  389   23   10
F  16 1366 1373 1379  15  7336  4831  2214      # 帧：worst CTS(min/avg/max) body render draw present
R   47   31    6    4   8136  47                # 结算：PF GREAT GOOD MISS score maxCombo
P 2  20000   38   88                            # 演奏：状态 曲目ms 已判音符 总音符
M    0    0    0    0    0                      # 每秒各路 delta 最小值
X   12    3    3    3    4                      # 每秒各路 delta 最大值
S  116   87                                     # 时钟对照：游戏秒 / RTC 秒（时基校验）
!  24835   123456                               # 长帧标记：帧耗时 / 当刻绝对毫秒
C 048,012,003,000,005|312,288,...|112,175,...   # 标定：当前 delta | 峰值 | 阈值（仅 Demo_Calib）
```

新增几行的用途：

- **`T` 行末尾的五路 delta**：定位串扰。正常按压目标轨一枝独秀（如 `0 30 801 28 5`）；
  若邻居也几百，说明手指压到了隔壁
- **`P` 行**：追"铺面消失"。`head` 追上 `count` 而 `songMs` 远小于谱面长度 → 音符被提前判完
- **`M`/`X` 行**：各路 delta 的每秒最小/最大值。`M` 长期贴着阈值 = 基线漂移；
  `X` 出现 1200~3300 = 测量被中断打断
- **`S` 行**：游戏秒 vs RTC 秒，用来验证时基准不准（两者必须 1:1 递增）
- **`!` 行**：帧耗时 > 500 ms 时自动输出，区分"真的卡住"和"计时跳变"

**USB 默认关闭**，在 **设置界面**（主菜单 S1 长按）里选到 `USB` 项、按 S2 打开。
这是照 LAB4 的做法：不在开机时初始化，等系统完全跑起来后由用户主动打开，
避免 D+ 上拉后的枚举窗口被开机初期的一堆初始化占用。

**用途**：

- `dt_ms` 的分布 → 判定窗口是否合适、是否需要整体偏移补偿
- `dt_ms` 的均值 → 玩家习惯偏向（配合液晶延迟实测决定 `JDG_OFFSET_MS`）
- `F` 行第一列 → 帧率是否稳定（应恒为 16，> 20 即有超预算帧）
- `F` 行后三列 → CTS 耗时是否超预算（avg 应 < 1500 µs）
- `R` 行 → 单局判定分布
- **`V` 行 → 本份日志对应的固件版本与参数**。没有它就无法判断某份 log 是哪个版本跑出来的
  （本项目真实踩过：多次分析建立在无法确认版本的日志上，导致错误归因）。
  退出设置界面时会额外打一条 `V tuned`，记录刚落盘的参数。

击打行先入队、在扫描窗口**之外**统一发送。USB 后端下发送本身非阻塞
（端点忙则丢弃），但入队/出队的结构保留 —— 换回 UART 后端时它仍然是必需的
（UART 一行 40 字节要阻塞 3.5 ms，放在采样窗口里会拉低输入采样率）。

开机横幅有特殊处理：上电时电脑往往还没打开串口，此时 V/K 行会**挂起**，
等检测到 USB 枚举完成（或拔插后重连）再补发 —— 否则"日志可追溯"就失效了。

### 一份实测样本

```
F  16 1366 1373 1379  15  7336  4831  2214    ← 60 fps；扫描 1.37 ms；渲染 7.3 ms
M    0    0    0    0    0                    ← 空闲 delta 最小值全 0（无基线漂移）
X   12    3    3    3    4                    ← 空闲 delta 峰值个位数（测量干净）
T   452 2  25700 25653 - 47 GREAT |   0   24  518   29    2   ← 按 lane2，邻居 5%
T   453 1  26200 26181 - 19 PERFECT |  35  815   31    2    0 ← 按 lane1，邻居 4%
R   47   31    6    4   8136  47               ← 一局结算
S  116   87                                    ← 游戏秒 / RTC 秒 1:1
```

> 竖线后面是击打瞬间五路原始 delta，用来判断串扰：正常按压目标轨一枝独秀，
> 若邻居也在几百的量级，说明手指压到了隔壁焊盘。

## 使用手册

### 快速开始

1. CCS 20.x 打开本工程 → `Project → Build`（栈 512 B / 堆 320 B 已配好）
2. 连接 LaunchPad，`Run → Debug`（或 MSPFlasher 烧 `Debug/LAB1.out`）
3. 上电后 LOGO 页按 **S1** 进入选曲页
4. **齿轮电位器**选曲 → **S2** 开始

### 按键与操作

| 场景 | 操作 | 功能 |
|---|---|---|
| LOGO | 任意键 | 进入选曲页 |
| 选曲 | 齿轮电位器 | 切换曲目（右侧显示该曲历史最高分） |
| | S2 短按 | 开始游戏 |
| | S2 长按 | 返回上一页 |
| | S1 长按 | 进入设置界面 |
| 设置 | 齿轮电位器 | 选项目（7 项） |
| | S1 / S2 短按 | 数值 − / + |
| | S2 长按 | **保存到 Flash** 并返回 |
| | S1 长按 | 直接返回（本次改动不落盘） |
| READY 倒计时 | S2 | 跳过倒计时 |
| 游戏中 | 5 路触摸焊盘 | 击打对应轨道 |
| | S2 短按 | 暂停 |
| | S1 长按 | 弃局回选曲 |
| 暂停 | S2 短按 | 进入恢复倒计时（谱面冻结 + 5 s 大字倒计时） |
| | S1 短按 / 长按 | 重开本曲 / 弃局回选曲 |
| 结算 | S2 / S1 | 重玩 / 回选曲 |

游戏中**按住焊盘时对应 LED 常亮**，松开即灭——这条通路不经液晶，延迟在微秒级，
用来补偿电容触摸没有触觉反馈的先天劣势。

### 设置项速查

| 项 | 含义 | 范围 / 步进 | 默认 |
|---|---|---|---|
| OFF | 判定偏移 JDG_OFFSET_MS | −100 ~ +100 ms，步 5 | 0 |
| ALN | 音符视觉对齐（px，正值上移） | −2 ~ +6，步 1 | +3 |
| SPD | 音符下落速度 | 40 ~ 120 px/s，步 10 | 60 |
| WIN | PERFECT 窗口（GREAT = 2×，GOOD = 10/3×） | 15 ~ 60 ms，步 5 | 30 |
| USB | USB CDC 遥测开关 | 按 S2 打开 | OFF |
| SENS | 触摸灵敏度倍率（实际阈值 = 基准 × SENS%） | 50 ~ 250%，步 10 | 100 |
| CLR | 清空全部曲目最高分 | **轻按 S2 执行**，S1 无效 | — |

设置页标题行右侧显示最近一局 dt 均值，用于标定 OFF：

```
打一局 → 记下 dt 均值 → OFF 调到 −dt → 再打一局确认接近 0
```

经验：ALN 对判定时机影响很小（移 3 px 只让 dt 变 7 ms），补偿偏置优先用 OFF；
固定 OFF 只能居中到长期平均，残留 ±12 ms 属于正常会话漂移。

### 标定触摸阈值

1. 把 `LAB1main.c` 的 `Game5K_Run()` 临时换成 `Demo_Calib()`，重新编译
2. 屏显柱状图，同时串口（USB 或 UART）输出 `C` 行：当前 delta | 峰值 | 阈值
3. 逐个按住每个焊盘约 1 秒，读 `C` 行的**峰值**列
4. 阈值取"该路峰值 × 40~50%"：
   - 改代码：`game/game_touch.c` 的 `Touch_Thresholds[5]`
   - 不改代码：设置页调 `SENS`（100 = 源码默认值）
5. 若相邻焊盘串扰明显，先抬 SENS，不要动 `TOUCH_DOM_SLACK`（默认 0 = 严格局部极大）

### 打开遥测（USB CDC）

1. 设置界面滚到 `USB`，按 **S2** 到 ON
2. 设备会进入 `USB ENUM` 等待页（最长 10 s），把 CPU 全让给枚举
3. 电脑上出现一个虚拟 COM 口（免驱，波特率对 CDC 无意义）
4. 用任意串口助手打开，应看到开机横幅：

```
V 5k-r62 spd=60 off=+ 10 aln=+ 3 win=30/60/100 sens=150
K thr=112,175,153,225,180
```

若 `USB` 打不开或 COM 口要等很久：先确认换过数据线（不是充电线），
再考虑把描述符裁成纯 CDC（见 README「当前状态 → 待办」）。

### 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| COM 口能看见但打不开 | 主机在探测不存在的 U 盘（描述符带 MSC），等 10~25 s 或裁描述符 |
| 开着串口时触摸变乱 | 应已修复（HAL 逐路关中断）；若复现，抬 SENS |
| 按一个键相邻轨 LED 也亮 | 应已修复（平局判给小轨号）；仍复现则记录 T 行五路 delta |
| 玩几分钟后铺面消失 | 应已修复（171.8 s 时基回绕）；若复现请附 `!` 长帧标记 |
| 手感突然变差、帧率掉到 35 fps | 开过 USB 后 LCD 的 SPI 被 SD 初始化改慢，`RTLCD_RestoreSpi()` 已处理 |
| 设置存不住 | 应已修复（校验和范围）；若复现请附 `V` 行 |
| 编译报找不到 `Game5K_Run` | 检查 `game/` 是否被排除在构建之外 |

### 加谱面

谱面是编译期固化的 C 数组（`game/game_charts.c`），格式：

```c
{ t_ms, lane, speed, judged, result, hold_ms }
```

- 必须按 `t_ms` **升序**
- 同轨下一个音符 ≥ `t_ms + hold_ms`
- 长条在 lane0/1 时，区间内不得有 lane0/1 的音符；lane3/4 同理；lane2 不限制
- 长条尾巴与同侧下一个音符留约 250 ms 余量
- 单曲上限 `CH_MAX_NOTES = 416`（超出会被截断）

# 5K 下落式节奏游戏 — MSP-EXP430F5529

> 在一块 8 KB RAM / 128 KB Flash 的 MSP430 上，用 5 路电容触摸焊盘做一个 60 fps 的下落式音游（5K 5 轨）。
> 无音频硬件，纯**目押**（看谱打点）。判定精度靠微秒级时基 + 时间戳判定，不靠帧率。

## 这是什么

MSP-EXP430F5529 是一块外设密度很高的实验板：102×64 单色液晶、5 路电容触摸焊盘、三轴加速度计、
齿轮电位器、8 个 LED、2 个机械按键、RTC、USB、SD 卡座。常见用法是逐个点亮它们。

本项目把这些外设**全部纳入同一个实时系统**，做成一个能玩的节奏游戏：

- 音符从屏幕顶部沿 5 条轨道下落，玩家在判定线处用手指击打对应的电容焊盘
- 判定精度以**毫秒**计：PERFECT ±30 ms / GREAT ±60 ms / GOOD ±100 ms
- 单色液晶跑**稳定 60 fps**（16.7 ms 帧周期）
- 板载无蜂鸣器/DAC，玩法是**目押**（纯视觉），靠 LED 与背光构建第二条快速反馈通道

## 玩法与操作

| 屏幕 | 操作 | 功能 |
|---|---|---|
| LOGO | 任意键 | 进入选曲页 |
| 选曲 | **齿轮电位器** | 切换曲目 |
| | S2 短按 | 确认开始 |
| | S2 长按 | 返回上一页 |
| READY 倒计时 | S2 | 跳过倒计时 |
| 游戏中 | **5 路电容焊盘** | 击打对应轨道 |
| | S2 短按 | 暂停 / 继续 |
| | S1 长按 | 弃局回选曲 |
| 暂停 | S2 / S1 短按 / S1 长按 | 继续 / 重开本曲 / 回选曲 |
| 结算 | S2 / S1 | 重玩 / 回选曲 |

游戏中**按住焊盘时对应 LED 常亮**（松开即灭）——这条通路不经过液晶，响应在微秒级，
用来补偿电容触摸没有触觉反馈的先天劣势。

内置 3 张测试谱面：`Easy 120 BPM`（88 音符）、`Normal 136 BPM`（250 音符）、`Hard 150 BPM`（412 音符），
每张谱面是一串 `(t_ms, lane)` 列表，编译期固化成 `Note[]` 数组（`game/game_charts.c`）：
`Note` 结构 8 字节，`t_ms` 为音符到达判定线的毫秒时刻，`lane` 为 0–4 轨道号。要换谱面，
按同样格式生成新的 `game_charts.c` 即可。

## 硬件资源占用

| 外设 | 引脚 / 资源 | 在本项目中的用途 |
|---|---|---|
| 电容触摸焊盘 ×5 | P6.0–P6.4（CB0–CB4） | 游戏 5 轨输入 |
| Comparator B + Timer_A1 | P1.6（CBOUT） | 触摸测量（fRO 弛豫振荡法） |
| LCD | UC1701，USCI_B1 SPI 12.5 MHz，片选 P7.4 | 102×64 显示 |
| LCD 背光 | Timer_B0.4 PWM | 节拍脉冲 / 亮度 |
| Timer_A0 | — | **40 ns 系统时基 + 帧对齐** |
| 机械按键 S1 / S2 | P1.7 / P2.2 | 菜单导航、暂停 |
| 齿轮电位器 | P6.5（ADC12 A5） | 选曲；预留调下落速度 |
| LED ×5 | P1.0–P1.5（经 `laneLed[]` 可改） | 击打/按住反馈 |
| USCI_A1 | P4.4 / P4.5 | **串口遥测 115200-8-N-1** |
| 加速度计 CMA3000-D01 | USCI_A0 SPI | 预留（重力模式） |
| 片上 Flash | INFO C @0x1880 | 预留（最佳成绩持久化） |

> 触摸与液晶**不冲突**：触摸走 Comparator B + Timer_A1，液晶走 USCI_B1，加速度计独享 USCI_A0。

## 技术要点

### 1. 判定用「时间戳」，不用「处理时刻」

这是整个设计能成立的前提。触摸扫描与渲染都是采样/帧式的，但**判定计算完全基于事件时间戳**：

```
音符到达判定线的时刻 t_ms  vs  击打事件的时间戳 songT
dt = t_ms - songT  →  分级
```

因此：

- **输入延迟 = 扫描采样误差（实测 ±1.3 ms），不是帧时间（16.7 ms）**
- 帧率下降只影响视觉流畅度，**不影响判定精度**

击打时间戳取「扫描中点」（扫描前后各读一次时基取中值），进一步压低抖动。

### 2. 40 ns 时基

Timer_A0 以 SMCLK 25 MHz 连续计数（1 tick = 40 ns），溢出中断扩展为 32 位。
读取时关中断 + 检查 `TAIFG` 补偿，避免「硬件已溢出但 ISR 未执行」的读数竞态
（该竞态会让耗时测量无符号回绕成 4.29 s）。

### 3. 影子缓冲 + 批量推屏

原厂 HAL 是**写穿式**的：每个绘制原语立刻发起 SPI 事务，逐像素绘制一帧约需 50 ms（≈20 fps），项目直接不可行。

本项目绕开它：绘制只写 `shadow[8][102]`，一帧结束再 `setAddress + writeData(102)` × 8 批量推屏，
**816 B ≈ 2.7 ms**，把帧预算从 200% 压到 16%。

### 4. 多键同时识别

TI 的 `TI_CAPT_Buttons()` 只返回**一个**主导电极，不能用于 5K。本项目用 `TI_CAPT_Custom()`，
它保留每路原始 `delta` 值，于是可以自己做逐路判定：

```c
pressed[i] = (delta[i] >= THR[i])                    /* 逐路阈值 */
          && (delta[i] + SLACK >= delta[i-1])        /* 主导键判据： */
          && (delta[i] + SLACK >= delta[i+1]);       /* 须为局部极大 */
```

主导键判据用「局部极大」而非「≥ 邻居 × 2/3」——后者挡不住相邻焊盘串扰
（实测打 lane1 时 lane0 会跟着误触发，见 `game_touch.c` 注释）。

### 5. 菜单键轮询取代 ISR

原厂 `HAL_Buttons` 的 ISR 有三个问题：不打时间戳、`buttonsPressed` 是赋值而非或（和弦会丢）、
实际没有消抖。菜单对时间精度要求只有 ±20 ms，因此改用主循环轮询 + 3 帧（≈50 ms）消抖，
天然规避全部三个问题。

### 6. 串口遥测

判定是看不见的，所以把关键数据打出来：击打事件（含 dt）、每秒帧/扫描统计、结算统计。
输出为纯 ASCII 行，任意串口助手可读，也可重定向存盘后用脚本分析。

## 实测性能

| 指标 | 实测值 | 备注 |
|---|---|---|
| 帧周期 | **16 ms（稳定 60 fps）**，最长帧 17 ms | 帧预算只需 ~8.7 ms |
| CTS 全扫耗时 | **1.29 ms**（空闲）/ ~1.4 ms（手指按住） | 抖动仅 ~16 µs，每帧可扫 3 次 |
| 影子缓冲推屏 | 816 B ≈ 2.7 ms | 占 60 fps 帧预算 16% |
| 内存占用 | RAM **4396 / 8192 B**（54%） | 影子 816 B + 谱面镜像 1280 B + 栈 512 B |
| | FLASH **30110 / 48000 B**（63%） | 仅低段（0x4400–0xFFFF）；高段 FLASH2 82 KB 全未用 |

> 数据来源：`Debug/LAB1.map` 与串口遥测的 `F` 行。

2. `Project → Clean`
3. `Project → Build`

## 上手：标定与三个前置实验

`game_main.h` 里提供了三个独立 Demo，把 `LAB1main.c` 主循环里的 `Game5K_Run()`
临时换成其一即可运行：

| 函数 | 用途 | 操作 |
|---|---|---|
| `Demo_LcdMotion()` | **液晶响应时间**——决定目押玩法是否可行 | 方块右移，S1 切 60/30/15 fps，用手机慢动作录像 |
| `Demo_ScanTiming()` | **CTS 全扫耗时**——决定采样率与判定精度上限 | 屏幕显示 500 次扫描的 min/avg/max (µs) |
| `Demo_Calib()` | **触摸焊盘标定**——定阈值、看串扰 | 屏显柱状图；串口输出当前值/峰值；S1 清峰值，S2 退出 |

### 标定步骤

1. 运行 `Demo_Calib()`，串口开 115200
2. 逐个**按住**每个焊盘约 1 秒，读 `C` 行的**峰值**列
3. 每路阈值取「该路峰值 × 40~50%」，填回 `game/game_touch.c` 的 `Touch_Thresholds[5]`
4. 同时记下「按 lane *i* 时邻居的峰值」：若相邻焊盘串扰明显导致误触发，把
   `TOUCH_DOM_SLACK`（默认 0 = 要求严格局部极大）按实测差值调整

## 串口遥测协议

**USCI_A1，P4.4 = TXD / P4.5 = RXD，115200-8-N-1**（SMCLK 25 MHz + UCOS16 过采样，误差 +0.06%）

四类行，纯 ASCII、空格分隔、可 grep：

```
T 00123 2    1240    1210  + 30 PERFECT    # 击打：序号 lane note_ms tap_ms dt_ms 判定
T 00124 0     ---    1300   --- WRONG      # 空按（该轨窗口内无音符）
F  16  1306  1314  1320                    # 帧：最长帧ms  CTS扫描 min/avg/max (µs)
R   40   34    9    5   7534  30           # 结算：PF GREAT GOOD MISS score maxCombo
C   48   12    3    0    5 |  312  288 ...  # 标定：当前 delta | 峰值 | 阈值（仅 Demo_Calib）
```

**用途**：

- `dt_ms` 的分布 → 判定窗口是否合适、是否需要整体偏移补偿
- `dt_ms` 的均值 → 玩家习惯偏向（配合液晶延迟实测决定 `JDG_OFFSET_MS`）
- `F` 行第一列 → 帧率是否稳定（应恒为 16，> 20 即有超预算帧）
- `F` 行后三列 → CTS 耗时是否超预算（avg 应 < 1500 µs）
- `R` 行 → 单局判定分布

击打行先入队、在扫描窗口**之外**统一发送（一行 40 字节 @115200 ≈ 3.5 ms，
若在采样窗口内阻塞会减少扫描次数、拉低输入采样率）。

### 一份实测样本

```
F  16  1291  1298  1304        ← 稳定 60 fps，CTS 全扫 1.29 ms
T     1 0    1200    1121 - 79 GOOD
T     2 2    1700    1635 - 65 GOOD
T     4 3    2700    2721 + 21 PERFECT
T    15 0     ---    8213  --- WRONG     ← 相邻焊盘串扰（已修）
R   40   34    9    5   7534  30
```
